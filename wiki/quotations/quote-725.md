# Computerworld — 1992-11-23

**Headline**: Microsoft lays out tiered DBMS plan Comdex

**Verdict**: HIGH prescience — score=5, confidence=3, horizon=SH-3y, pipeline=P2

## Quote

> The bad news is that Access alone should not be viewed as a tool that can craft all the applications in an enterprise.

## Rationale

From 1992–1995, Microsoft Access quickly became popular for small workgroup and departmental applications, but enterprises continued to build their core systems on client–server platforms such as Oracle, IBM DB2, Sybase, and later Microsoft SQL Server, typically using tools like PowerBuilder, Visual Basic, and 4GLs rather than Access. Access’s technical limits in scalability, multi-user concurrency, security, and manageability meant it was rarely adopted as the primary platform for all enterprise applications, instead serving as a desktop or departmental front end to larger databases. This matches Kastner’s warning that Access should not be viewed as a tool to build all enterprise applications, which was borne out both in the mid‑1990s and in its long-term positioning as a niche productivity database rather than an enterprise-wide application platform.
