# Digital LinkWorks: Delivering Solutions to MIS and End-Users

> Aberdeen Group profile evaluating Digital Equipment Corporation's LinkWorks, a document management and workflow platform for enterprise groupware. Introduces the concept of 'Enterprise Groupware' built on distributed object technology and contrasts it with first-generation products such as Lotus Notes and Microsoft Exchange. Argues that LinkWorks uniquely satisfies both MIS and end-user requirements through open databases, OLE integration, and a component-based development model.


_Published 1995, author **Aberdeen Group**, type **product-profile**._


## Top observations

- Aberdeen defines 'Enterprise Groupware' as a new category built on distributed object technology using open databases, enabling drag-and-drop solution assembly, component reuse, and location-independent data access — distinct from first-generation proprietary groupware.
- Aberdeen states that applying the Enterprise Groupware litmus test to Lotus Notes makes clear it is a first-generation product — more like a standard development environment supporting multiple tools, not an object-oriented enterprise groupware system.
- Aberdeen notes that Microsoft Exchange, like Lotus Notes, fails the Enterprise Groupware litmus test because it lacks object-oriented architecture and component-based composition.
- LinkWorks server supported on Digital UNIX, HP-UX, SCO Unix, OpenVMS, IBM AIX; Windows NT 3.5 support announced as forthcoming.
- LinkWorks desktop clients supported: Windows 3.1, Windows for Workgroups, Motif (Digital/HP/IBM), OS/2 Presentation Manager, and Macintosh OS.
- LinkWorks supports Oracle, CA Ingres, Microsoft SQL Server, and Informix as repository databases; Sybase support was planned.
- Digital Equipment Corporation introduced LinkWorks in 1994 and had just announced version 3 at the time of the study (July 1995), described as 'years ahead of more traditional groupware providers.'
- LinkWorks uses a modular three-tier client/server architecture. A Transaction Dispatch Facility optimizes server processes; a Cell architecture allows cluster-level fault isolation so server failure has only local impact.
- LinkWorks supports highly granular access control: up to eight predefined access rights plus custom rights, assignable per object at creation time, applicable to individual users, groups, or combinations.
- Every LinkWorks object is assigned a globally unique object identifier (OID); every instance is saved with metadata recording who modified it, when, and what changed, enabling complete revision history.
- LinkWorks integrates with Windows via OLE Automation, allowing Windows OLE-capable applications to become objects in the LinkWorks repository. Digital and Microsoft collaborated on porting NT to Alpha and integrating OLE with Digital's object broker.
- End-users can specify document routing via a graphical interface: drag-and-drop recipients from an org chart, assign conditional branches, and automate notification when objects are modified.
- LinkWorks persists user desktop state server-side: when a user logs in from any machine or OS, the environment is reconstructed exactly as left, with all objects and files accessible.
- The LinkWorks Application Plus Objects (APO) interface allows legacy applications and data to be encapsulated as first-class objects; requires a developer fluent in both objects and the legacy system.
- Aberdeen research found that groupware products do not usually satisfy all stakeholders simultaneously: department-acquired solutions rarely meet MIS rigor; MIS-acquired solutions rarely meet end-user ease-of-use expectations.
- Aberdeen identifies cross-organizational support as a critical success factor for enterprise groupware adoption, and positions it as a key market differentiator.
- Aberdeen recommends corporations take 'a long hard look at LinkWorks' for competitive advantage and cost savings through object technology; also recommends confronting legacy integration challenges because the ROI of integration is substantial.
- Applications and templates can be packaged into software components and installed or deinstalled across any number of LinkWorks servers via disk, tape, CD-ROM, or the corporate messaging infrastructure.
- LinkWorks supports scripts that can be recorded or executed on any desktop or server, and can be encapsulated and used as objects within solutions.
- Aberdeen notes that current (1995) groupware tools enable workgroup collaboration but in closed, proprietary environments; they require significant retraining, do not incorporate existing applications, and require specialist developers for even slightly process-driven tasks.
- Aberdeen states that unifying object-oriented technology is 'leaving the research lab and finding its way into the market as an integration framework' encompassing disparate clients, servers, and applications as of 1995.
- LinkWorks enforces security at the object level, providing controlled access even for applications that are not 'security aware'; all data access is governed by user logon and centrally maintained object permissions.
- MIS requires standardized rapid development, multi-vendor business process automation, controlled data access, and use of existing infrastructure; end-users require ease of use, searchable common repository, familiar desktop tools, and flexible collaboration — these goals are frequently in conflict.
- Developers build applications from a toolkit of common classes and components; modifications to a component are immediately reflected in every solution using it. Components can be built from scratch or derived from existing ones.
- Aberdeen recommends companies confront legacy integration difficulties: once integrated, legacy applications gain full leverage in LinkWorks solutions; legacy programmers gain valuable OO skills enabling them to tackle mission-critical reengineering.
