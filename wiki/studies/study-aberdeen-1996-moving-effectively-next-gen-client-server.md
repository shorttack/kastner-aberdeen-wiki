# Moving Effectively To Next-Generation Client-Server Development

> Aberdeen Group white paper, sponsored by Gupta Technologies, argues that first-generation client-server application development environments (CADEs) such as Visual Basic and PowerBuilder are 'topping out' and recommends immediate adoption of next-generation CADEs. The study provides an evaluation framework for next-generation CADE selection and positions Gupta's Centura product as the leading choice for organizations migrating from first-generation toolsets.


_Published 1996, author **Aberdeen Group**, type **white-paper**._


## Top observations

- Most popular first-gen CADEs are Microsoft Visual Basic and Sybase/Powersoft PowerBuilder; major users in many cases contemplating new toolsets
- 6-7 times growth in database size over 18 months in many data warehouse cases; requires next-gen CADE scalability
- TI-Microsoft initiative shows no signs of finishing; only fruit is TI's administrator-intensive departmental Arranger; Microsoft shows no intention of targeting fully-featured high-end development
- Sybase/Powersoft committed to using repository from recently acquired company; delivery date not yet clear; use for next-gen technology even further off
- Full-featured object-based repository; supports Oracle and Sybase data-dictionary metadata import; Team Object Manager for repository administration
- Beta testing in 2Q96; provides drag-and-drop application partitioning across 2-tier and 3-tier architectures; supports DCE, TCP/IP, Network OLE communications
- Internet QuickObjects for Web-enabled SQL data access; Centura Web Data Server replicates data from multiple databases with firewall security; Java compilation planned for subsequent release
- First-gen CADEs provide little software for scaling development process or automating unfamiliar tasks for training; communication problems increase as square of programmer count
- First-gen CADEs provide little application partitioning, query optimization, or load balancing; applications slow drastically as users/database size increase
- Absence of automated deployment/maintenance software requires physical installation at each site, local admin burden, repeated redeployment on upgrades
- First-gen CADEs lack repositories and application-repartitioning GUIs for adapting to 3-tier and Intranet architectures
- Complex/data-intensive applications require reversion to 4GL or 3GL scripting; most productivity gains lost for large applications
- Version control, project management, regression testing; Centura: Team Object Manager + Team Object Repository + integrated PVCS version control
- Client-server partition via drag-and-drop VPE; Centura Application Server targeted at 2-tier and 3-tier partitioning
- Centura supports Novell Tuxedo TP monitor with Tuxedo Deployment Suite; middleware access to IBM CICS and Encina; 3-Tier Wizard for simplified TP programming
- Centura SAL provides extensive database/gateway operations; Centura Ranger for heterogeneous replication across multiple vendors' databases
- Design (Rational Rose/LogicWorks ERWin links), programming/testing (debugger, incremental compiler), deployment (repository-based), maintenance (SQLConsole integration)
- Full-featured object-oriented repository; Team Object Repository on standard RDBMSs; open to Oracle and Sybase metadata; key differentiator vs. Visual Basic and PowerBuilder
- Centura Data Model Viewer for business modeling; reverse engineering of schemas from modeler, CASE tools, or RDBMS metadata
- Average start-to-ship development speed improvement ~35% after 1+ year learning curve, per fragmentary studies cited by Aberdeen
- Visual Basic, PowerBuilder, Delphi, SQLWindows; best for departmental/simple/client-centric apps not needing scale
- Gupta Centura, Symantec, Unify, Compuware Uniface; appropriate for scaling up existing first-gen applications and new moderate-scale development
- Oracle, Sybase, Informix, CA-Ingres, Progress CADEs; useful for installed RDBMS base for upgrading from 4GL and data-intensive applications
- Forte, Dynasty, Seer Technologies; best for very complex and very data-intensive new applications with multiple suppliers' databases
- In short to medium term, users may have serious concerns about VB/PowerBuilder shops' ability to solve first-gen problems without bringing in new toolset
