# Maxtor RAMP Disk Storage Usage Questionnaire v2

> Refined second version of the Aberdeen Group telephone survey questionnaire for the Maxtor RAMP project. Streamlines the v1 instrument to 17 survey questions and a demographic section, with key enhancements: per-OS storage breakdowns (Q4.1-Q4.3) for mainframe / Windows / Unix separately, introduction of a 1-7 Likert willingness-to-tradeoff scale (Q9) testing three distinct cost-performance scenarios (50% cost reduction with lower availability; 30% with less availability; 30% with same availability), vendor engagement probing (Q10-Q11), restore frequency measurement (Q12), static data application identification (Q14), and a refined terminology awareness battery testing five terms. The instrument was used to collect data from approximately 70 enterprise IT decision-makers.


_Published 2003, author **Peter S. Kastner; David Hill (Aberdeen Group)**, type **market-study**._


## Top observations

- Telephone survey questionnaire — version 2; refined and streamlined from v1
- Q1: Which OSes does your organization use AND which are you directly responsible for? (Mainframe / Windows / Unix-Linux)
- Q4.1-Q4.3: Per-OS capacity share / DAS-SAN-NAS mix / 12-month growth / max fill rate — separately for mainframe / Windows / Unix
- Q4.2 and Q4.3 use identical structure; both excluded from mainframe category
- Q5: Online disk copies (excluding original) / tape copies (each generation = one copy)
- Q6: Data that is effectively read-only or seldom written — closed transaction logs / old e-mail — but cannot yet be archived to tape
- Q7: What applications fall under the read-only/seldom-written category? (Open-ended)
- Q8: What percent of total storage is the read-only/seldom-written data?
- Q9: Rate willingness to trade off on 3 scenarios (1=unwilling to tradeoff; 7=sign me up today)
- Q9(a): Higher capacity + slightly less performance + slightly less availability + ~50% cost reduction
- Q9(b): Current disk sizes + current performance + slightly less availability + ~30% cost reduction
- Q9(c): Current disk size + current performance + current availability + ~30% cost reduction
- Q10: Has your current storage supplier discussed low-cost disk options with you? (Supplier name?)
- Q11: If yes [vendor discussed low-cost options] — plans to purchase in next 12 months (1=Not at all; 7=Already have)
- Q12: How often do you restore one or more volumes from storage failure — weekly / monthly / quarterly / semi-annually / annually / less than annually
- Q14: Single applications with very large non-volatile/static data — video data / images / data warehouse detailed / old e-mails
- Q15: SCSI / FC / ATA percentage + drive sizes + rotational speeds — open-systems disk arrays only
- Q16: Five specific backup failure modes — offline window / job failure rate / cannot guarantee restore / management burden / restore time too long
- Q17: Active archiving / online archiving / mezzanine storage / nearline storage / low-cost storage — all five tested
- Q9's three scenarios implicitly test whether midline is a substitute (Scenario C) or complement (Scenarios A/B) for existing storage
- [UNVERIFIED]
- Q9(a) states cost reduction ""on the order of 50%"" for higher-capacity / less-available option
- Q1 and Q4.3 treat Unix, Linux, and 'open systems' as a single category
- Survey jumps from Q12 to Q14 — Q13 missing or removed in v2 revision
- Q10 asks for supplier name when vendor has discussed low-cost disk — competitive intelligence design
