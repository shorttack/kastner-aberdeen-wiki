# Digital LinkWorks

> version_at_study=3.0; lifecycle_note=Discontinued after DEC was acquired by Compaq (1998); product not carried forward under HP.


## Top observations

- Failed: Digital LinkWorks was discontinued after Compaq acquired DEC in 1998 for $9.6B; Lotus Notes and Microsoft Exchange/Outlook dominated enterprise groupware `[ps=5]` — [[study-aberdeen-1995-digital-linkworks]]
- End-users can specify document routing via a graphical interface: drag-and-drop recipients from an org chart, assign conditional branches, and automate notification when objects are modified. `[ps=4]` — [[study-aberdeen-1995-digital-linkworks]]
- LinkWorks persists user desktop state server-side: when a user logs in from any machine or OS, the environment is reconstructed exactly as left, with all objects and files accessible. `[ps=4]` — [[study-aberdeen-1995-digital-linkworks]]
- The LinkWorks Application Plus Objects (APO) interface allows legacy applications and data to be encapsulated as first-class objects; requires a developer fluent in both objects and the legacy system. `[ps=4]` — [[study-aberdeen-1995-digital-linkworks]]
- LinkWorks enforces security at the object level, providing controlled access even for applications that are not 'security aware'; all data access is governed by user logon and centrally maintained object permissions. `[ps=4]` — [[study-aberdeen-1995-digital-linkworks]]
- LinkWorks integrates with Windows via OLE Automation, allowing Windows OLE-capable applications to become objects in the LinkWorks repository. Digital and Microsoft collaborated on porting NT to Alpha and integrating OLE with Digital's object broker. `[ps=3]` — [[study-aberdeen-1995-digital-linkworks]]
- Applications and templates can be packaged into software components and installed or deinstalled across any number of LinkWorks servers via disk, tape, CD-ROM, or the corporate messaging infrastructure. `[ps=3]` — [[study-aberdeen-1995-digital-linkworks]]
- LinkWorks supports scripts that can be recorded or executed on any desktop or server, and can be encapsulated and used as objects within solutions. `[ps=3]` — [[study-aberdeen-1995-digital-linkworks]]
- The LinkWorks server maintains a complete record of every object regardless of which server it resides on, enabling enterprise-wide search across the entire LinkWorks environment. `[ps=3]` — [[study-aberdeen-1995-digital-linkworks]]
- LinkWorks provides a central Administration Manager to control the entire environment; the Cell cluster architecture is event-based and allows centralized management of performance characteristics. `[ps=3]` — [[study-aberdeen-1995-digital-linkworks]]
- Digital Equipment Corporation introduced LinkWorks in 1994 and had just announced version 3 at the time of the study (July 1995), described as 'years ahead of more traditional groupware providers.' `[ps=1]` — [[study-aberdeen-1995-digital-linkworks]]
- Aberdeen predicts Digital LinkWorks will become the standard for Enterprise Groupware, displacing first-gen Notes/Exchange in large organizations `[ps=1]` — [[study-aberdeen-1995-digital-linkworks]]
- LinkWorks desktop clients supported: Windows 3.1, Windows for Workgroups, Motif (Digital/HP/IBM), OS/2 Presentation Manager, and Macintosh OS. `[ps=0]` — [[study-aberdeen-1995-digital-linkworks]]
- LinkWorks supports Oracle, CA Ingres, Microsoft SQL Server, and Informix as repository databases; Sybase support was planned. `[ps=0]` — [[study-aberdeen-1995-digital-linkworks]]
- LinkWorks supports highly granular access control: up to eight predefined access rights plus custom rights, assignable per object at creation time, applicable to individual users, groups, or combinations. `[ps=0]` — [[study-aberdeen-1995-digital-linkworks]]
- At time of publication, Digital maintained a World Wide Web server for LinkWorks at http://www.digital.com/info/linkworks, demonstrating early enterprise software web presence in 1995. `[ps=0]` — [[study-aberdeen-1995-digital-linkworks]]
- LinkWorks server supported on Digital UNIX, HP-UX, SCO Unix, OpenVMS, IBM AIX; Windows NT 3.5 support announced as forthcoming. — [[study-aberdeen-1995-digital-linkworks]]
- LinkWorks uses a modular three-tier client/server architecture. A Transaction Dispatch Facility optimizes server processes; a Cell architecture allows cluster-level fault isolation so server failure has only local impact. — [[study-aberdeen-1995-digital-linkworks]]
- Every LinkWorks object is assigned a globally unique object identifier (OID); every instance is saved with metadata recording who modified it, when, and what changed, enabling complete revision history. — [[study-aberdeen-1995-digital-linkworks]]
- Developers build applications from a toolkit of common classes and components; modifications to a component are immediately reflected in every solution using it. Components can be built from scratch or derived from existing ones. — [[study-aberdeen-1995-digital-linkworks]]
