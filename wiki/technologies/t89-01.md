# IBM AS/400 (OS/400)

> Aberdeen rated AS/400 as immature in 1989: lacking C compiler, 1MB program limit, journaling reduces TPS by up to 60%.


## Top observations

- AS/400 evolved through iSeries, System i to IBM i on Power Systems; still actively supported in 2026 with 100,000+ installations `[ps=5]` — [[study-1989-vidmar-as400-hp3000-and-metadata-a32d04]]
- Journaling and Checksum recommended for production systems can reduce throughput by up to 60% `[ps=3]` — [[study-1989-vidmar-as400-hp3000-and-metadata-a32d04]]
- Not yet mature: no C compiler, 1MB program size limit, frequent OS patch tapes, OS/400 immature `[ps=2]` — [[study-1989-vidmar-as400-hp3000-and-metadata-a32d04]]
- AS/400 lacks growth path today; multiple-AS/400 clustering not a reasonable alternative `[ps=1]` — [[study-1989-vidmar-as400-hp3000-and-metadata-a32d04]]
- AS/400 OS/400 single-level storage more likely to require lengthy restores after system failure than conventional midrange approach `[ps=1]` — [[study-1989-vidmar-as400-hp3000-and-metadata-a32d04]]
- AS/400 B60 offers ~25% less performance than HP 3000 Model 70; B70 approximates Model 70 `[ps=0]` — [[study-1989-vidmar-as400-hp3000-and-metadata-a32d04]]
- High risk: MIS staff retraining, software conversion, new sales analysis system from scratch, cost escalation foreseeable `[ps=0]` — [[study-1989-vidmar-as400-hp3000-and-metadata-a32d04]]
