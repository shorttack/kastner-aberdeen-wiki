# Tandem Object Relational Data Mining Architecture

> Never achieved de facto standard status; Compaq acquisition 1997 led to deprioritization; architectural vision later vindicated by MPP analytics


## Top observations

- Create de facto standard SQL interface between data mining tools and RDBMS using SQL extensions — [[study-1997-tandem-object-relational-data-mining-architecture-2d8139]]
- Data-manipulation functions integrated into RDBMS; enterprise executes against data directly in warehouse; no flat-file extract required — [[study-1997-tandem-object-relational-data-mining-architecture-2d8139]]
- Scales from SMP to MPP as data mining demands grow; runs on ServerWare/NT or Himalaya servers — [[study-1997-tandem-object-relational-data-mining-architecture-2d8139]]
- Determine what data will likely return best results — precedes algorithm execution — [[study-1997-tandem-object-relational-data-mining-architecture-2d8139]]
- Data scrubbing — removing data and field inconsistencies — [[study-1997-tandem-object-relational-data-mining-architecture-2d8139]]
- Coding the data — formatting data to work best with selected algorithm — [[study-1997-tandem-object-relational-data-mining-architecture-2d8139]]
- Algorithm execution and results review; re-tuning model and re-running algorithm iteratively — [[study-1997-tandem-object-relational-data-mining-architecture-2d8139]]
- Object Relational Data Mining architecture available Q3 1997 on ServerWare/NT and Himalaya; credit card/micromerchandising/claims packages available without SQL extensions immediately — [[study-1997-tandem-object-relational-data-mining-architecture-2d8139]]
- Tandem's ORDM architecture will become an end-to-end enterprise weapon for competitive advantage; Aberdeen believes enterprises can look to it as the standard solution — [[study-1997-tandem-object-relational-data-mining-architecture-2d8139]]
- Compaq acquired Tandem in 1997; ORDM architecture was deprioritized; de facto standard SQL data mining interface goal not achieved; Oracle/Microsoft/Informix did not adopt the standard — [[study-1997-tandem-object-relational-data-mining-architecture-2d8139]]
- Parallel-scalable architecture; 5 integrated data mining partner algorithms; solutions packages with vertical templates; consulting services — end-to-end capability — [[study-1997-tandem-object-relational-data-mining-architecture-2d8139]]
- ORDM increases overall reliability of supplier code; saves data mining suppliers from writing redundant code; encourages more value-added development — [[study-1997-tandem-object-relational-data-mining-architecture-2d8139]]
