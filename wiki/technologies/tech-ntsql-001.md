# Microsoft SQL Server for NT

> Deployed in call center operations. Documented: database crashes requiring hours/days to rebuild, frequent corruption, poor cache management, inadequate referential integrity and replication. Lacked row-level locking.


## Top observations

- Frequent database crashes requiring hours or days to rebuild — [[study-1997-nt-case-41-56aa2e]]
- More frequent than desired or expected; time-consuming recovery — [[study-1997-nt-case-41-56aa2e]]
- Poor; known bugs unfixed across three micro-revisions — [[study-1997-nt-case-41-56aa2e]]
- Cache management, referential integrity, replication, messaging, log management, SQL debugging tools all viewed as inadequate — [[study-1997-nt-case-41-56aa2e]]
- Concern over Year 2000 (Y2K) compliance of SQL Server — [[study-1997-nt-case-41-56aa2e]]
