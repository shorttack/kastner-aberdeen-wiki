# Three-tier (and 'three-tier plus') architecture

> New architectural pattern requiring CADE support; Centura Application Server targeted at 3-tier development.


## Top observations

- Decision-support implementations grow 3-5x every 18 months; three-tier architecture required to avoid scalability/performance problems — [[study-aberdeen-1996-iq-software-www-reporting]]
- IQ has had a Unix and NT three-tier architecture since 1995; one year of refinement gives it advantage over would-be competitors — [[study-aberdeen-1996-iq-software-www-reporting]]
- WWW-enabled applications will require sophisticated three-tier architectures; will create a flurry of announcements among suppliers — [[study-aberdeen-1996-iq-software-www-reporting]]
- Three-tier architecture became the standard for web-based enterprise applications and BI tools by 2000-2005; prediction proved accurate — [[study-aberdeen-1996-iq-software-www-reporting]]
- First-gen CADEs provide little software for scaling development process or automating unfamiliar tasks for training; communication problems increase as square of programmer count — [[study-aberdeen-1996-moving-effectively-next-gen-client-server]]
- First-gen CADEs provide little application partitioning, query optimization, or load balancing; applications slow drastically as users/database size increase — [[study-aberdeen-1996-moving-effectively-next-gen-client-server]]
- Absence of automated deployment/maintenance software requires physical installation at each site, local admin burden, repeated redeployment on upgrades — [[study-aberdeen-1996-moving-effectively-next-gen-client-server]]
- First-gen CADEs lack repositories and application-repartitioning GUIs for adapting to 3-tier and Intranet architectures — [[study-aberdeen-1996-moving-effectively-next-gen-client-server]]
- Visual Basic, PowerBuilder, Delphi, SQLWindows; best for departmental/simple/client-centric apps not needing scale — [[study-aberdeen-1996-moving-effectively-next-gen-client-server]]
- Oracle, Sybase, Informix, CA-Ingres, Progress CADEs; useful for installed RDBMS base for upgrading from 4GL and data-intensive applications — [[study-aberdeen-1996-moving-effectively-next-gen-client-server]]
- Forte, Dynasty, Seer Technologies; best for very complex and very data-intensive new applications with multiple suppliers' databases — [[study-aberdeen-1996-moving-effectively-next-gen-client-server]]
- 3-tier architecture became the standard enterprise application pattern throughout the late 1990s and 2000s, exactly as Aberdeen predicted; web tier, application server, database tier became ubiquitous — [[study-aberdeen-1996-moving-effectively-next-gen-client-server]]
- Senior management consensus: productivity, customer satisfaction, revenue enhancement from effective IS strategy; 3-Tier architecture enables this — [[study-aberdeen-1996-object-oriented-three-tier-plus-computing]]
- Automate business information flows, improve productivity, add revenue opportunities, cut costs; replace batch mainframe with real-time processes — [[study-aberdeen-1996-object-oriented-three-tier-plus-computing]]
- Graceful evolution to new technologies; investment protection; SMP clustering and board-level upgrades increasingly popular — [[study-aberdeen-1996-object-oriented-three-tier-plus-computing]]
- Lower cost hardware (PC/LAN/mid-tier); reuse of existing mainframe applications; API bridges to legacy data; rapid application prototyping — [[study-aberdeen-1996-object-oriented-three-tier-plus-computing]]
- Approximately 25 million business client workstations shipped worldwide in 1995 — [[study-aberdeen-1996-object-oriented-three-tier-plus-computing]]
- Residual value of mainframe software portfolio will continue to decline during second half of 1990s as PCs handle more processing — [[study-aberdeen-1996-object-oriented-three-tier-plus-computing]]
- Mainframe installed base shrank but did not disappear; IBM z-series still significant for banking/insurance; client-server/3-tier replaced most new development — [[study-aberdeen-1996-object-oriented-three-tier-plus-computing]]
- Hardware, RDBMS platforms now stable, reliable, well-understood; missing pieces from 1992 (OOP tools, TP performance, data replication, network management) now in production — [[study-aberdeen-1996-object-oriented-three-tier-plus-computing]]
